## 从Kali到BlackArch

如果你在三年前告诉我，我会放弃Kali Linux转投BlackArch，我大概会觉得你疯了。毕竟Kali是行业标准，是OSCP认证的官方指定发行版，是每个网安新手的必修课。但三年后的今天，我不仅完成了这个迁移，而且发自内心地觉得——**早该这么做了**。

这篇文章不是要劝所有人都换到BlackArch。恰恰相反，BlackArch并不适合大多数人。但如果你和我一样，已经是Arch Linux的深度用户，对系统有强烈的定制需求，又恰好从事安全相关工作，那这篇文章或许能引起你的共鸣。

先说说我的背景。Arch Linux是我的主力系统，我享受rolling release带来的最新软件，也享受从零搭建自己桌面环境的掌控感。我的日常离不开`pacman -S`，我的Hyprland配置经过了无数次的调整和ricing——窗口边框的阴影、终端的配色方案、状态栏的每一个模块，都是反复打磨的结果。

换句话说，**我已经离不开Arch的生态了**。


## Kali很好，但它不属于我

Kali基于Debian Testing分支，使用APT包管理器。对于一个习惯了`pacman`和AUR的人来说，每次切到Kali都像穿了一双不合脚的鞋——不是不能走路，但总觉得哪里不对。

更让我困扰的是Kali的更新策略。Kali采用“半滚动发布”模式，每年推出4个主要版本。这意味着如果你想用上某个工具的最新版本，可能需要等上好几个月。对于安全研究来说，**工具的新旧往往直接决定了你能不能在最新的漏洞上抢到先机**。

还有一点：Kali预装了大约600个工具。听起来很多对吧？但对于一个习惯了“想要什么就自己装什么”的Arch用户来说，这种“给你什么你就用什么”的思路，总让我觉得少了点什么。


## 第一次接触

第一次听说BlackArch，是在某个技术社区的讨论里。有人提到BlackArch实际上有**超过2800个安全工具**，是Kali的4倍以上。这个数字让我很好奇，但真正打动我的不是数量，而是它的安装方式。

BlackArch本质上不是一个新的操作系统——**它是Arch Linux的一个“覆盖层”** 。你不需要重装系统，只需要在现有的Arch安装上添加BlackArch仓库，然后按需安装工具。一条命令就能搞定：

```bash
curl -s https://blackarch.org/strap.sh | sudo bash
```

这意味着什么？意味着**我可以保留我精心打磨了三年的Arch系统、我的Hyprland配置、我的Quickshell、我所有的ricing成果**，然后在这个基础上，获得一个拥有近3000个安全工具的巨大武器库。

这对我来说简直是降维打击式的吸引力。


## 全是工具

Kali的做法是把几百个工具预装好，开箱即用。这对新手来说很友好——你不用思考需要什么，系统都帮你装好了。但代价是：你有一大堆可能永远用不到的工具占着磁盘空间。

BlackArch的做法完全不同。它的工具仓库有超过2800个工具，按类别组织，但**你可以只安装你需要的那些**。想装一个就装一个，想装一组就装一组。

```bash
# 安装单个工具
sudo pacman -S <工具名>

# 安装整个分类
sudo pacman -S blackarch-<分类名>
```

这种“工具超市”的模式，让我可以在需要的时候随时“采购”，而不是被迫接受一个固定的工具集。对于喜欢掌控一切的Arch用户来说，这种自由度简直是天生的契合。


## 性能与响应速度

一个意外的惊喜是性能。有用户在相同硬件上对比过Kali和BlackArch，发现BlackArch的安装和运行明显更快、响应更灵敏。我自己也有类似的感受——也许是Arch本身更轻量的缘故，也许是少了那些预装服务的拖累，总之在同样的笔记本上，BlackArch跑起来确实更“跟手”。


## Ricing友好

这一点可能对大多数网安从业者来说无关紧要，但对我很重要。

Kali有自己固定的主题和桌面配置，虽然可以改，但总有种“在别人的系统上装修”的感觉。而BlackArch跑在Arch之上——**我的Hyprland配置可以直接复用，我的Quickshell快捷键不用重新适应，我的终端配色方案、我的字体设置、我的所有dotfiles，全部原封不动地工作**。

作为一个花了大量时间打磨桌面环境的人，这种“无缝迁移”的体验是无价的。


## 不是没有代价

当然，BlackArch不是完美的。它的学习曲线比Kali陡峭得多。如果你不熟悉Arch Linux的安装和配置，BlackArch可能会让你非常头疼。滚动更新也意味着偶尔会遇到包冲突或兼容性问题。

但对我来说，这些“代价”恰好是我作为一个三年Arch用户已经熟练掌握的技能。**我不是在学习一个新的发行版，我只是在为我熟悉的系统增加一个新的仓库。**


## 总结：为什么我选择了BlackArch

回过头来看，我的选择其实很自然：

| 维度 | Kali Linux | BlackArch |
|------|------------|-----------|
| 底层 | Debian + APT | Arch + pacman |
| 工具数量 | ~600个 | 2800+个 |
| 安装方式 | 完整发行版 | **可在现有Arch上叠加** |
| 更新策略 | 半滚动，每年4版 | 滚动更新 |
| 定制性 | 有限 | **极高** |
| 对Arch用户友好度 | 需要切换包管理器 | **原生体验** |

**Kali是给所有人的网安发行版，BlackArch是给Arch用户的网安发行版。**

如果你已经在Arch的生态里扎了根，如果你享受用`pacman -S`而不是`apt install`，如果你不愿意为了安全工具放弃自己打磨了三年的桌面环境，你适合blackarch。
